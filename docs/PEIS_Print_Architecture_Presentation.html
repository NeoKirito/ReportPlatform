EVOLUTION & COMPARISON

架构演进：以前的困境 vs 现在的革新

以往旧模式痛点 (Legacy)

旧 IIS 方案

IIS 强依赖与死锁崩溃风险

原报表服务寄宿在 IIS 中，并发高时容易出现应用程序池卡死，部署依赖复杂环境。

浏览器打印体验割裂、无法静默

必须在浏览器中弹出 PDF 窗口，由护士/医生每次手动选择打印机并点击确定，效率低下且容易选错。

多硬件（条码机/A4/双面）无法分流

打完体检条码接着打体检报告时，浏览器始终记住上次的标签机，导致 A4 纸经常打在条码机上废纸。

模板排错极为隐蔽

FRX 模板 Base64 嵌在数据库中，字段映射与多子表查询没有标准化调试工具与日志跟踪。

全新集成打印方案 (Modern)

.NET 10 + Agent

独立微服务 & 100% 绿色便携

基于 .NET 10 AOT/独立发布，解压即用无需装运行时，直接以高性能 WebAPI 承载高并发渲染。

工作站智能 Agent 与硬件静默直连

内置专用 SumatraPDF 静默引擎 + WebView2 高清硬件加速预览，彻底告别浏览器打印弹窗。

按单据类型（djid）自动记忆分流

条码自动走条码机，登记单走普通 A4，个检报告走高速双面机，本地记忆，零人工干预。

业务无感平滑迁移

Java 业务层沿用原有 PDF 拼装与加盖水印逻辑，数据库 54+ 种 FRX 模板不用改动一行代码。

SYSTEM ARCHITECTURE

端到端交互拓扑与执行流转

1. 业务触发 2. 模板渲染 3. 智能路由 4. 终端出纸
STEP 01
前端操作 (Browser)

医生/护士点击“预览”或“打印”。
POST /desktopReportDelivery
传递参数：体检结果ID、模板ID (djid)。

★ 前端无需知道 Agent 或打印机名
STEP 02
Java 业务中枢

1. 抓取客户端 IP (request.getRemoteAddr())
2. 调用 ReportApi 渲染基础 PDF
3. 执行原有盖章/多单据合并
4. 上传最终 PDF 到投递队列。

★ 保留所有复杂业务后处理
STEP 03
PEIS.ReportApi 核心

1. 查询 xt_bgdy_djwh_zzj 取 FRX & SQL
2. FastReport 渲染引擎生成流
3. 投递服务按 IP 匹配当前在线的工作站 Agent。

★ 毫秒级 IP 拓扑自动映射
STEP 04
PEIS.PrintAgent 终端

1. 本地工作站托盘拉取 PDF 文件
2. 预览：唤起 WebView2 顶层置顶
3. 打印：读取本地 djid 打印机记忆，SumatraPDF 静默物理出纸。

★ 零弹窗、自动化无感出纸

DEEP DIVE INTO TEMPLATES

模板底层机制：数据库存储、动态 SQL 与渲染

1. 模板表结构 (xt_bgdy_djwh_zzj)

所有 54+ 套报表均维护在 SQL Server 统一管理，支持热更新：

djid: varchar(20)
主键。如 jktjbbd(个检), tjdjd(登记单), xmtm(条码)
dj_frx: varchar(max)
FastReport XML 模板的 Base64 编码字符串
djsql: text
参数化取数 SQL（支持存储过程与动态拼接）

2. 主从多数据集装配

单张复杂报表可能包含多个数据集查询，ReportApi 自动进行聚合注入：

主表: djid = 'jktjbbd'

输出主数据集 Master（体检人员基本信息、体检号等）。

子表: djid = 'jktjbbd_1' ~ '_N'

输出科室小结、检验明细、影像图谱等多明细表。

多媒体 & 签名

支持 HTTP 图片 URL / Base64 签名在 FRX 中动态渲染。

3. 核心动态参数映射

Java 请求传入 JSON 参数，ReportApi 引擎完成占位符动态绑定：

@grtjgcjjgid 个人体检结果主ID
@tjryid 体检人员唯一ID
@dwtjgcjjgid 单位体检结果ID
@sfxmddid 收费项目大单ID
已完整验证并兼容的核心模板分类：
健康体检总报告 jktjbbd
体检登记单 / 导检单 tjdjd
采血 / 项目条码标签 xmtm
职业病 / 团体汇总表 zyb_tjbg / dw...
SMART WORKSTATION ROUTING

工作站 Agent：打印机类型智能记忆与静默引擎

什么是“按单据类型（djid）记忆打印机”？

医院科室通常同时连接多台物理打印设备。传统方案无法分辨是打条码还是打报告。新 Agent 在每台工位本地维护映射关系：

xmtm (项目条码)
Zebra ZD888 条码打印机
tjdjd (体检登记单)
HP LaserJet M403 A4黑白
jktjbbd (体检报告)
Canon C3226 彩色双面机

内置 SumatraPDF 物理静默打印

采用 SumatraPDF 独立命令行驱动，绕过操作系统厚重 PrintDialog 弹窗；打印命令直接直达 Windows Spool 打印后台，出纸快、不占用前台焦点、绝不卡死主界面。

Agent 端三种工作模式
模式 1：高清置顶预览 (Preview) WebView2 内核

前端触发预览指令，Agent 弹出高清 PDF 预览窗口，顶部提供打印、翻页、缩放与另存为功能。

模式 2：静默直接打印 (Silent Print) 无感出纸

配置 `SilentPrint=true` 后，前端点击打印，本地对应打印机直接出纸，屏幕不弹任何干扰窗口。

模式 3：首次确认 & 记忆模式 人性化自适应

首次遇到未记忆的单据类型时弹出选机确认框，用户选择一次后自动存入本地，后续自动进入静默模式。

DEPLOYMENT & OPERATIONS

极简部署指引与生产落地步骤

1. ReportApi (服务器)

核心服务端

解压绿色包到服务器（如 `D:\PEIS\ReportApi`）。

// config.ini 配置
Port=82
ConnectionString=Server=192.168.0.237;Database=TJXT0616;UID=sa;PWD=...;
双击 启动服务.cmd 即启动，支持查看状态与关闭。

2. Java 业务后端

业务中间件

修改 `application.yml` 并更新发布最新 JAR 包。

# application.yml
report:
fastReportUrl: http://192.168.0.237:82/...
desktop-delivery:
enabled: true
url: http://192.168.0.237:82/api/...
保留原有 `/exportPdf`，新增 `/desktopReportDelivery`。

3. PrintAgent (工作站)

工位客户端

各护士站/医生站电脑解压独立 Agent 包。

// agent.ini 配置
ServerUrl=http://192.168.0.237:82
SilentPrint=false / true
PrintBackend=SumatraPDF
双击 Start-DesktopAgent.cmd 自动进驻系统托盘。
高可靠性保证：心跳断线自动重连；工作站 IP 变化自动感知并注册；支持无网络脱机保护。
