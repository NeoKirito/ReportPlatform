EVOLUTION OF PRINTING ARCHITECTURE

三代演进：从 Active-X、IIS 到现代微服务与 Agent

1 第一代：C/S 控件时代

Grid++Report 6
  • 强依赖 IE 浏览器：必须在客户端安装 Active-X 控件。
  • 客户端维护困难：工位电脑系统版本不一致，注册表与控件频繁损坏。
现状：已全面被 Web 化淘汰

2 第二代：IIS FastReport 时代

IIS + Browser Print
  • IIS 宿主卡死：高并发生成 PDF 时应用程序池死锁或内存泄露。
  • 无法静默打印：每次打印必须弹浏览器窗口，人工选择确认。
  • 设备易串机：打完条码打报告，A4 容易误打到条码纸上废纸。
现状：本次改造重点替代对象

3 第三代：现代微服务协同 (当前)

.NET 10 + Agent
  • 绿色微服务：.NET 10 高性能独立引擎，脱离 IIS。
  • 单据类型打印机记忆：条码/登记单/报告按 djid 自动分流出纸。
  • SumatraPDF 静默 + WebView2 预览：直达 Spool 后台零弹窗。
现状：100% 兼容旧模板，已上线运行

LEGACY HTML-TO-PDF DEEP DIVE

历史 HTML 转 PDF 机制剖析：为什么逐步被 FastReport 替代？

历史 ConvertHtmlStringToPdf.java 的转换链路

1 前端 Vue 页面构建大长 HTML 网页（如集宁区中蒙医院专属版式）
2 Spire.PDF HtmlConverter 调用本地 plugins/QtWebKit 插件转为 PDF
3 调用 importImage(white.png) 遮盖 Spire 试用版水印
4 调用 RemoveBlankPages 剔除尾部多余空白页
5 PDFBox PDFMergerUtility 将 HTML 封面与 FastReport 科室明细合并

为什么全面回归 FastReport 原生模板？

1. 多线程并发容易崩溃死锁

Qt WebKit 是本地 C++ 进程，批量并发转换时极易耗尽内存或引起主线程等待锁死。

2. 分页截断不可控与断行撕裂

HTML 分页难以精确计算毫米级边距，文字经常被 A4 页面硬生生切成上下两半。

3. FastReport 原生渲染极致稳定且快

由 FastReport 统一绘制封面/目录/警示灯，耗时从 3~5 秒缩短至 200~400 毫秒，零外部依赖。

DEPLOYMENT & ROUTING

打印机智能分流记忆与生产部署实施

1. ReportApi (报表服务器)

服务端

解压便携包到固定目录（如 `D:\PEIS\ReportApi`）。

// config.ini 配置
Port=82
ConnectionString=Server=...;Database=TJXT0616;...
双击 启动服务.cmd 即启动，支持状态检查与关闭。

2. Java 业务后端

业务中间件

修改 `application.yml` 配置并发布最新 JAR。

# application.yml
report:
fastReportUrl: http://...:82/...
desktop-delivery:
url: http://...:82/api/...
保留原 `/exportPdf`，新增 `/desktopReportDelivery`。

3. PrintAgent (工作站)

工位终端

各工位电脑解压专属 Agent 独立包。

// agent.ini 配置
ServerUrl=http://192.168.0.237:82
SilentPrint=false / true
PrintBackend=SumatraPDF
双击 Start-DesktopAgent.cmd 自动进驻托盘。
单据类型记忆机制生效：`xmtm` 自动分流至条码机，`tjdjd` 自动分流至 A4 激光机，`jktjbbd` 自动分流至双面彩色机，首次选择后永久生效。

SQL TOOLKIT FOR OPS & SUPPORT

实施与售后运维高频实用 SQL 工具箱

快速排查 · 模板调试 · 状态维护
1. 人员与报告生成/打印状态全字段排查 排查体检进度 
SELECT 
    g.grtjgcjjgid, r.xm, r.xb, r.sfzh, g.tjbh,
    g.tjzt,         -- 体检状态(8为已总检)
    g.bgsczt,       -- 报告生成状态(0未生成 1已生成)
    g.bgurl,        -- 磁盘落地路径
    d.dycs, d.dysj  -- 打印次数与最后打印时间
FROM pe_grtjgcjjg g WITH(NOLOCK)
INNER JOIN pe_tjryxx r ON g.tjryid = r.tjryid
LEFT JOIN pe_tj_bgdyjl d ON g.grtjgcjjgid = d.grtjgcjjgid
WHERE r.xm = '邓鹏宇' OR g.tjbh = '2026090001';
💡 用途：客户说“报告打不出”或“找不到人”时，一眼看清是未总检、未生成还是路径丢失。
2. 报表模板 (FRX Base64) 与主子查询 SQL 提取 报表排错 
-- 提取某个报表（主表及附属子查询）
SELECT djid, djmc, xh, djsql, 
       LEN(dj_frx) AS frx_length,
       dj_frx -- Base64 编码的 FRX 模板内容
FROM xt_bgdy_djwh_zzj WITH(NOLOCK)
WHERE djid = 'jktjbbd' OR djid LIKE 'jktjbbd[_]%'
ORDER BY xh, djid;
💡 用途：排查报告模板数据源报错、字段缺失或自定义修改 SQL 取数逻辑。
3. 强制清空旧报告缓存（支持重新生成） 报告重新生成 
-- 清除指定人员已生成状态，强制下次请求重新触发渲染
UPDATE pe_grtjgcjjg 
SET bgsczt = '0', bgurl = NULL 
WHERE grtjgcjjgid = 'A5C0C3C57D99488E8B06D67677263B44';

-- 清除打印次数加锁限制（允许重新打印）
UPDATE pe_tj_bgdyjl 
SET dycs = 0 
WHERE grtjgcjjgid = 'A5C0C3C57D99488E8B06D67677263B44';
💡 用途：医生修改结论后报告未刷新，或打印达到上限被锁定时一键重置。
4. 检查人员分检小结、异常标识与总检综述 分检与总检排查 
SELECT 
    a.xmmc, a.jczt, b.tjxmxj, b.tjjy, 
    b.gxsfyc -- 1为异常，0为正常
FROM pe_tjxmxq a WITH(NOLOCK)
LEFT JOIN pe_tjxmxq_zdxj b ON a.tjxqid = b.tjxqid
WHERE a.grtjgcjjgid = 'A5C0C3C57D99488E8B06D67677263B44' 
  AND a.deleted != 1;
💡 用途：排查“总检综述为什么没带出来”、“分检无建议是否填充”及异常过滤问题。
