# PEIS 桌面报告预览与打印完整使用说明

## 1. 这套程序分别做什么

整套功能由四部分组成：

| 程序 | 安装位置 | 作用 |
|---|---|---|
| PEIS 前端 | 浏览器 | 用户点击“预览”或“打印”，不需要知道 Agent 名称和打印机名称 |
| HealthCheck Java 后端 | 业务服务器 | 保留原 `PdfupdateUtil.exportPdf` 编排，生成最终 PDF 后投递到 ReportApi |
| PEIS.ReportApi | 报告服务器 | 查询模板和数据、运行 FastReport 生成 PDF，并把最终 PDF 投递给对应电脑 |
| PEIS.PrintAgent | 每台需要预览/打印的 Windows 电脑 | 下载 PDF、显示预览、按 `djid` 记住打印机、执行静默打印 |

正常流程如下：

```text
浏览器前端
  → Java /exportTemplate/desktopReportDelivery
  → Java 原 PdfupdateUtil.exportPdf
  → PEIS.ReportApi /BaseInfo/Report/GetReportByJson 生成 PDF
  → Java 完成原有合并或后处理
  → Java 把最终 PDF、浏览器 IP、djid 投递到 PEIS.ReportApi
  → ReportApi 按浏览器 IP 自动找到同一台电脑的 PrintAgent
  → PrintAgent 打开 PDF，或直接发送到以前选择的打印机
```

前端不传 Agent 名称。物理打印机名称也不保存在前端和 Java 数据库中，而是保存在对应工作站本地。

## 2. 本说明使用的服务器地址

正式示例统一使用：

```text
ReportApi 服务器：http://192.168.0.237:82
```

如果正式服务器地址不是这个，请同时修改：

1. Java `application.yml` 的两个 ReportApi 地址。
2. 每台工作站 `agent.ini` 的 `ServerUrl`。

不要把测试电脑地址 `192.168.0.88` 带到正式环境。

## 3. 部署 PEIS.ReportApi

### 3.1 解压

在报告服务器解压：

```text
PEIS.ReportApi-Portable-win-x64-20260902-printer-memory-v5.zip
```

建议放到固定目录，例如：

```text
D:\PEIS\ReportApi
```

不要直接在 ZIP 压缩包中运行。

### 3.2 配置端口和数据库

编辑解压目录中的 `config.ini`：

```ini
Port=82
ConnectionString=Server=数据库地址;Database=数据库名;User ID=用户名;Password=密码;Encrypt=False;TrustServerCertificate=True;
```

普通部署只需要维护这两项：

- `Port`：HTTP 服务端口，当前为 82。
- `ConnectionString`：原报告模板和业务数据所在 SQL Server 连接串。

发布 ZIP 中的连接串故意留空，不包含真实数据库密码。

### 3.3 启动与关闭

双击：

```text
启动服务.cmd
```

查看状态：

```text
查看状态.cmd
```

关闭服务：

```text
关闭服务.cmd
```

正常启动后可访问：

```text
http://127.0.0.1:82/health
```

局域网其他电脑应访问：

```text
http://192.168.0.237:82/health
```

如果本机能访问、其他电脑不能访问，需要检查 Windows 防火墙是否允许 TCP 82 入站。

## 4. 配置和部署 Java 后端

Java 配置应为：

```yaml
report:
  fastReportUrl: http://192.168.0.237:82/BaseInfo/Report/GetReportByJson
  desktop-delivery:
    enabled: true
    url: http://192.168.0.237:82/api/report-deliveries
```

含义：

- `fastReportUrl`：Java 原 `exportPdf` 用它生成基础 PDF。
- `desktop-delivery.enabled`：是否开启新桌面预览投递接口。
- `desktop-delivery.url`：Java 生成最终 PDF 后上传到这里。

最新 JAR：

```text
E:\lkProject\HealthCheckHv3.0_20260616\target\PhysicalExaminationSystem-V3.0-20260616.jar
```

替换正式 JAR 前应先备份旧 JAR。新功能是新增接口，原 `/exportPdf` 没有删除。

## 5. 在每台工作站安装 PrintAgent

### 5.1 解压

在需要预览或打印报告的 Windows 电脑上解压：

```text
PEIS.WorkstationAgent-Portable-win-x64-20260902-printer-memory-v6.zip
```

建议目录：

```text
D:\PEIS\PrintAgent
```

Agent v6 是 `win-x64 self-contained` 包，目标电脑不需要另外安装 .NET 10。

PDF 预览使用 WebView2。大多数安装 Edge 的 Windows 系统已经具备 WebView2 Runtime；如果提示预览组件启动失败，再安装 WebView2 Runtime。

### 5.2 最简单配置

编辑 `agent.ini`：

```ini
ServerUrl=http://192.168.0.237:82
SilentPrint=false
DefaultPrinter=
PrintBackend=DryRun
PrintExecutable=
PrintArgumentsTemplate={file} {printer} {copies} {duplex}
```

只预览 PDF 时，只需要确认 `ServerUrl` 正确。

### 5.3 启动与关闭

启动：

```text
Start-DesktopAgent.cmd
```

关闭：

```text
Stop-DesktopAgent.cmd
```

Agent 名称默认使用 Windows 电脑名，例如 `PC-20210421ZVBD`，无需人工配置，也无需告诉前端。

## 6. 三种使用模式

### 6.1 只预览，不打印

前端提交：

```json
{
  "action": "Preview",
  "report": {
    "grtjgcjjgidArr": ["C48E053041174B41B32C9CE9EB5ECE7F"],
    "templateid": "jktjbbd",
    "filename": "123456"
  }
}
```

调用地址：

```text
POST /TJ/exportTemplate/desktopReportDelivery
```

结果：

1. Java 生成最终 PDF。
2. ReportApi 自动匹配浏览器所在电脑的 Agent。
3. Agent 打开 PDF 预览窗口。
4. 不需要打印机配置，也不会保存打印机记录。

### 6.2 显示预览，由用户确认打印

`agent.ini`：

```ini
SilentPrint=false
```

前端提交 `Print` 或 `PreviewAndPrint`：

```json
{
  "action": "PreviewAndPrint",
  "copies": 1,
  "duplex": false,
  "report": {
    "grtjgcjjgidArr": ["C48E053041174B41B32C9CE9EB5ECE7F"],
    "templateid": "jktjbbd",
    "filename": "123456"
  }
}
```

首次打印 `jktjbbd`：

1. Agent 显示 PDF。
2. 顶部显示本机打印机下拉列表。
3. 用户选择打印机。
4. 点击“打印”。
5. Agent 保存 `jktjbbd → 选择的打印机`。

以后再次打印 `jktjbbd` 时，下拉框会自动选中上次使用的打印机，用户不需要重新选择。

### 6.3 静默打印，不显示 PDF

`agent.ini`：

```ini
SilentPrint=true
DefaultPrinter=DASCOM DL-620Z
PrintBackend=Command
PrintExecutable=D:\PEIS\Tools\医院批准的PDF打印程序.exe
PrintArgumentsTemplate=--file {file} --printer {printer} --copies {copies} --duplex {duplex}
```

实际参数格式必须与所使用的打印程序一致，上面的 `--file` 等只是示例。Agent 支持的替换占位符是：

| 占位符 | 内容 |
|---|---|
| `{file}` | Agent 下载后的 PDF 完整路径，自动加引号 |
| `{printer}` | Windows 打印机完整名称，自动加引号 |
| `{copies}` | 打印份数 |
| `{duplex}` | 是否双面打印，`true` 或 `false` |

静默打印的打印机选择顺序：

1. 该 `djid` 以前保存的打印机。
2. `DefaultPrinter` 指定的打印机。
3. Windows 默认打印机。

新 `djid` 第一次静默打印后，使用的打印机也会被保存。以后即使修改 `DefaultPrinter`，旧 `djid` 仍继续使用历史选择。

### 6.4 DryRun 是什么

```ini
PrintBackend=DryRun
```

表示只验证下载、选打印机、进入打印队列、返回完成状态，但不会真的出纸。

正式物理打印必须改成：

```ini
PrintBackend=Command
```

并正确配置 `PrintExecutable` 和 `PrintArgumentsTemplate`。

## 7. 打印机记忆规则

Java 自动把：

```text
report.templateid
```

作为 `djid` 发送给 Agent。例如：

```text
djid=jktjbbd
```

Agent 保存文件：

```text
%ProgramData%\PEIS\PrintAgent\printer-selections.json
```

示例内容：

```json
{
  "jktjbbd": "DASCOM DL-620Z",
  "guide-sheet": "HP LaserJet M404"
}
```

记录保存在 ProgramData，所以更换或升级 Agent 文件夹后仍然保留。

如果已保存的打印机后来被卸载，Agent 会自动移除失效记录：

- 交互模式：下次重新选择。
- 静默模式：改用 `DefaultPrinter` 或 Windows 默认打印机并保存。

## 8. 清空打印机记录

双击 Agent 目录中的：

```text
清空打印机记录.cmd
```

它会：

1. 停止当前 PrintAgent。
2. 删除 `%ProgramData%\PEIS\PrintAgent\printer-selections.json`。
3. 保留 Agent 身份，不会改变电脑匹配关系。

清除后重新双击 `Start-DesktopAgent.cmd`。

之后每个 `djid` 会按首次使用处理。

## 9. 前端不需要传什么

正常前端调用不需要传：

- `stationId`
- Agent 名称
- Windows 电脑名
- 物理打印机名称
- `printerRole`

ReportApi 根据浏览器 IP 自动匹配 Agent。打印机由 Agent 根据 `djid` 在本机决定。

只有多台 Agent 在线、反向代理又没有正确传递浏览器 IP，导致无法唯一匹配时，前端才需要调用工作站列表接口让用户选择工作站。

## 10. 状态说明

ReportApi 桌面任务状态：

| 状态 | 含义 |
|---|---|
| `Queued` | 已创建任务 |
| `Downloading` | Agent 正在下载 PDF |
| `Opened` | Agent 已打开 PDF 预览 |
| `Printing` | 已进入打印过程 |
| `Completed` | 打印后端执行完成；DryRun 下只代表模拟完成 |
| `Failed` | 下载、预览或打印失败 |
| `Expired` | 任务过期 |

Java 当前本地状态：

```text
Queued → Generating → Delivering → Delivered
                         ↘ Failed
```

Java 的 `Delivered` 表示最终 PDF 已成功上传到 ReportApi，并不等同于 Agent 已经 `Opened` 或 `Completed`。如前端必须展示电脑最终状态，Java 后续还需要使用 `remoteJobId` 代理查询 ReportApi 状态。

## 11. 一键测试预览

在 Agent 目录双击：

```text
一键启动并测试.cmd
```

脚本会：

1. 自动启动 Agent。
2. 调用旧兼容接口生成真实测试 PDF。
3. 验证 PDF 文件头和大小。
4. 不传 `stationId` 投递到本机 Agent。
5. 等待状态变为 `Opened`。

命令行测试：

```powershell
powershell -ExecutionPolicy Bypass -File .\Test-DesktopReportDelivery.ps1 `
  -ServerUrl http://192.168.0.237:82 `
  -ReportServerUrl http://192.168.0.237:82 `
  -Action Preview `
  -Djid jktjbbd
```

打印测试时建议先保持 `PrintBackend=DryRun`：

```powershell
powershell -ExecutionPolicy Bypass -File .\Test-DesktopReportDelivery.ps1 `
  -ServerUrl http://192.168.0.237:82 `
  -Action PreviewAndPrint `
  -Djid jktjbbd
```

## 12. 水印说明

`PEIS.ReportApi` 已实现应用层水印能力：

```text
读取维护库 dbo.qx_hospital.jgmc
→ FastReport Prepare
→ 逐页叠加水印
→ 导出 PDF
```

但是当前旧兼容接口 `/BaseInfo/Report/GetReportByJson` 默认没有开启这层应用水印。当前报告中出现的水印可能来自 FRX 模板；Java 的 `/exportPdfWithWatermark` 还会单独增加医院名称和患者姓名水印。

在没有确认正式水印规则前，不应直接全局开启 ReportApi 水印，否则某些流程可能出现双水印。建议先明确：

1. 哪些报告需要水印。
2. 水印只显示医院名，还是医院名加患者姓名。
3. 是否继续保留 Java `/exportPdfWithWatermark`。
4. FRX 模板中是否已经包含水印。

## 13. 常见问题

### 13.1 返回 404 Not Found

通常是 ReportApi 版本过旧或 Java/测试脚本地址写错。检查：

```text
http://服务器:82/api/report-deliveries/stations
```

### 13.2 返回 409，Agent offline

检查：

1. 对应电脑是否启动 `PEIS.PrintAgent.exe`。
2. `agent.ini` 的 `ServerUrl` 是否正确。
3. 工作站能否访问 ReportApi 服务器端口 82。
4. ReportApi 与 Agent 是否使用配套的新版本。

### 13.3 多个 Agent 在线，无法自动匹配

检查反向代理是否保留浏览器真实 IP，例如 `X-Forwarded-For` 或 `X-Real-IP`。正常同网段直连不需要手工工作站名称。

### 13.4 状态 Completed，但打印机没出纸

先检查：

```ini
PrintBackend=DryRun
```

DryRun 本来就不会出纸。生产应配置 `Command` 和真实打印程序。

### 13.5 提示打印机不存在

保存的打印机名称必须与 Windows“打印机和扫描仪”中的名称一致。打印机改名或卸载后，Agent 会移除旧记录。

### 13.6 静默打印没有历史打印机

设置：

```ini
DefaultPrinter=本机打印机完整名称
```

或者先在 `SilentPrint=false` 模式下完成一次交互选择。

### 13.7 PDF 预览打不开

检查 WebView2 Runtime；也可先确认下载的文件以 `%PDF-` 开头且大小不为零。

## 14. 推荐上线顺序

1. 在报告服务器部署 ReportApi，配置数据库并验证 `/health`。
2. 用旧请求测试 `/BaseInfo/Report/GetReportByJson` 能返回正常 PDF。
3. 部署新的 Java JAR，确认 `desktop-delivery.enabled=true`。
4. 先选一台测试工作站部署 Agent。
5. 保持 `SilentPrint=false`、`PrintBackend=DryRun`，测试预览和打印机记忆。
6. 配置医院批准的命令行打印程序。
7. 保持 `PrintBackend=Command`，先测试一台真实打印机。
8. 确认纸张、份数、双面参数正确后，再设置 `SilentPrint=true`。
9. 最后批量部署其他工作站。

不要一开始就对所有电脑开启真实静默打印。
