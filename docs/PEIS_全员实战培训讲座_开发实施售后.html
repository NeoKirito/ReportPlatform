FOUNDATION & PACKAGE SYSTEM

体检底层基石：三级字典结构、套餐配置与价格策略

1. 经典“科室-大项-小项”三级结构
Level 1: 科室 (pe_ksxx)
内科、外科、放射科、检验科、彩超室...
Level 2: 收费项目大单 (pe_tjdd_sfxmdd)
血常规五分类、肝功七项、胸部CT、腹部彩超...
Level 3: 检查项目小项 (pe_tjdd_jcxmddnr)
白细胞计数(WBC)、谷丙转氨酶(ALT)、收缩压...

大单负责计费与导检，小单负责具体指标、单位与参考值范围。

2. 套餐分类与组合模板 (`pe_tctp`)
  • 人群分类套餐：入职体检、中老年套餐、妇女两癌筛查、公务员体检。
  • 职业危害套餐：接噪人员套餐、粉尘危害套餐、高温作业套餐。
  • 组合打包规则：套餐内包含多个收费大项，支持套餐一键应用与个性化自由加减项。
★ 支持按性别、婚否自动限制项目（如未婚限制妇检）。
3. 灵活的价格体系与结算策略
  • 标准物价与协议价：对齐医院物价标准编码，支持单位协议折扣率（如 8 折、75 折）。
  • 个人支付 vs 单位统筹：支持混合支付模式（如单位定额 500 元，超出部分个人自费补差）。
  • 弃检与退费机制：未检或弃检项目支持明细退费，自动重新计算总金额。
★ 财务收费凭条即时生成，防止漏费、少费。
SEPARATE INSPECTION

科室分检工作站：智能录入、异常判定与知识库

1. 临床科室智能小结与常用短语库

内科、外科、眼科、耳鼻喉等科室，录入小项后支持快速生成科室小结：

一键全正常：所有指标正常时，自动填入“心肺腹未见明显异常”或“未见异常”，将 `gxsfyc` 标记为 0。
异常自动提取小结：勾选阳性体征（如“窦性心动过速”），自动提取为诊断小结，将 `gxsfyc` 标记为 1（异常），并自动带出该诊断对应的健康指导建议。
科室暂存与封单：录入完毕点击“本科室完成”，锁定本科室数据，防止其他工位误修改。
2. 医技检验自动化计算与参考值范围

检验科（LIS）、心电图及设备数据的自动化解析：

多维度参考值动态比对：根据体检者的性别、年龄段自动匹配参考值区间（如男性与女性血红蛋白正常值范围不同）。
危机值自动预警：检测到极度异常指标（如血糖 > 20 mmol/L 或严重贫血），系统即时标红警示并自动生成危机值通知单。
计算公式与衍生指标：支持公式自动化计算（如通过身高体重自动算 BMI、肾小球滤过率 eGFR 计算等）。
COMPLETE INSPECTION ENGINE

总检智能决策引擎：综述建议生成与参数控制体系

1. 阳性异常汇总策略

总检医生打开人员时，系统自动扫描所有已完成科室的 `pe_tjxmxq_zdxj`：

异常过滤：按 `gxsfyc=1` 筛选所有异常指标，自动剔除“未见异常”等正常项目。
跨科室互斥与归并：例如心电图与内科均有心动过速时，智能合并或按权重保留。
数据来源: pe_tjxmxq_zdxj
2. 系统核心总检参数配置 (`PE_XTCS_CSSZ`)
总检综述是否只显示异常
控制是否将 gxsfyc=0 的正常项排除在综述外。
分检无建议是否填充综述到建议
科室只填了诊断未填建议时，自动用综述填充建议。
总检建议显示项目名
输出建议时前置显示【项目名称】。
总检合并异常
多条异常建议合并成段或独立成行输出。
表: PE_XTCS_CSSZ
3. 主检审核与电子签名加盖
  • 总检完成封锁：总检审核通过后，置 `pe_grtjgcjjg.tjzt = 8`，所有分检科室变为只读，防止结果被篡改。
  • 电子手签自动关联：读取审核医生工号绑定的签名高清透明图片（`image/qm/`），渲染到报告尾页。
  • 总检撤销机制：如需修改必须主管医师执行“撤销总检”，保留修改审计日志。
表: pe_tjzjshjl (总检记录)
REPORT PLATFORM MICROSERVICE

报表微服务：.NET 10 + FastReport 渲染引擎底层架构

1. .NET 10 高性能微服务
  • 绿色便携免安装：独立分发（Self-Contained），不需要目标服务器装 .NET 环境与 IIS。
  • 100% 接口全兼容：向下无缝兼容 Java 调用的 `/BaseInfo/Report/GetReportByJson` 接口。
  • 内存池与高并发：采用内存流（MemoryStream）生成 PDF，零临时垃圾文件堆积。
工程: PEIS.ReportPlatform
2. FRX 模板机制与多子表查询
  • 存储表：`dbo.xt_bgdy_djwh_zzj`，Base64 编码存放 FRX XML。
  • 主子数据集聚合：以 `jktjbbd_1` ~ `_N` 命名的多条 SQL 自动组装成多表 DataSet 注入模板。
  • 动态多媒体：超声彩超图谱通过 HTTP URL 或 Base64 实时渲染至报告中。
表: xt_bgdy_djwh_zzj (54+模板)
3. 报告存储与秒开机制
  • 物理路径：`E:\resourceFile\tjPdf\{yyyy-MM-dd}\{filename}.pdf`。
  • 数据库记录：`pe_grtjgcjjg.bgurl`。
  • 秒开原则：文件存在直接读磁盘返回（几毫秒）；重新总检自动删除旧文件并重新生成。
配置: file.path: E:/resourceFile/
PRINT AGENT & ROUTING

集成打印：单据类型智能分流与工作站 PrintAgent

1. 解决医院错打/废纸痛点：按单据类型（djid）记忆设备

一个体检科室往往同时连接条码机、普通 A4 激光机和彩色双面报告机。新 Agent 在每台工位本地维护映射关系：

xmtm (采血条码) ➔ Zebra / 得力条码标签机
tjdjd (体检登记单) ➔ HP LaserJet A4 黑白激光机
jktjbbd (体检总报告) ➔ Canon 高速彩色双面机
2. SumatraPDF 物理静默引擎与 IP 自动寻址
  • SumatraPDF 内核静默直出：绕过 Windows 弹窗与浏览器打印控件，命令直达 Spool 驱动后台，零弹窗、不卡界面。
  • WebView2 高清置顶预览：预览模式下调起本地硬件加速预览窗口，支持翻页、缩放与另存为。
  • IP 自动智能匹配：前端只发指令，ReportApi 根据客户端 IP 自动匹配当前在线工位 Agent，前端与 Java 零感知。

自助机与智能排队

SQL TOOLKIT FOR OPS & SUPPORT

实施与售后运维高频实用 SQL 工具箱

快速排查 · 模板调试 · 状态维护
1. 人员与报告生成/打印状态全字段排查 排查体检进度 
SELECT 
    g.grtjgcjjgid, r.xm, r.xb, r.sfzh, g.tjbh,
    g.tjzt,         -- 体检状态(8为已总检)
    g.bgsczt,       -- 报告生成状态(0未生成 1已生成)
    g.bgurl,        -- 磁盘落地路径
    d.dycs, d.dysj  -- 打印次数与最后打印时间
FROM pe_grtjgcjjg g WITH(NOLOCK)
INNER JOIN pe_tjryxx r ON g.tjryid = r.tjryid
LEFT JOIN pe_tj_bgdyjl d ON g.grtjgcjjgid = d.grtjgcjjgid
WHERE r.xm = '邓鹏宇' OR g.tjbh = '2026090001';
💡 用途：客户说“报告打不出”或“找不到人”时，一眼看清是未总检、未生成还是路径丢失。
2. 报表模板 (FRX Base64) 与主子查询 SQL 提取 报表排错 
-- 提取某个报表（主表及附属子查询）
SELECT djid, djmc, xh, djsql, 
       LEN(dj_frx) AS frx_length,
       dj_frx -- Base64 编码的 FRX 模板内容
FROM xt_bgdy_djwh_zzj WITH(NOLOCK)
WHERE djid = 'jktjbbd' OR djid LIKE 'jktjbbd[_]%'
ORDER BY xh, djid;
💡 用途：排查报告模板数据源报错、字段缺失或自定义修改 SQL 取数逻辑。
3. 强制清空旧报告缓存（支持重新生成） 报告重新生成 
-- 清除指定人员已生成状态，强制下次请求重新触发渲染
UPDATE pe_grtjgcjjg 
SET bgsczt = '0', bgurl = NULL 
WHERE grtjgcjjgid = 'A5C0C3C57D99488E8B06D67677263B44';

-- 清除打印次数加锁限制（允许重新打印）
UPDATE pe_tj_bgdyjl 
SET dycs = 0 
WHERE grtjgcjjgid = 'A5C0C3C57D99488E8B06D67677263B44';
💡 用途：医生修改结论后报告未刷新，或打印达到上限被锁定时一键重置。
4. 检查人员分检小结、异常标识与总检综述 分检与总检排查 
SELECT 
    a.xmmc, a.jczt, b.tjxmxj, b.tjjy, 
    b.gxsfyc -- 1为异常，0为正常
FROM pe_tjxmxq a WITH(NOLOCK)
LEFT JOIN pe_tjxmxq_zdxj b ON a.tjxqid = b.tjxqid
WHERE a.grtjgcjjgid = 'A5C0C3C57D99488E8B06D67677263B44' 
  AND a.deleted != 1;
💡 用途：排查“总检综述为什么没带出来”、“分检无建议是否填充”及异常过滤问题。
